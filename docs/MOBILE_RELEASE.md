# 移动端版本发布与回退

## 基线与配置

历史线上页面显示“性格探索”和更新后的本地保存说明；无法仅靠这些文案确定Cloudflare部署提交。代码基础为PR #1，head f2b70414cf9a5176c5dcb1472521cfccfcbd49b4。合并时核对PR未出现新提交。

目标：生产分支 main，npm run build，输出 dist，Node 24，根路径。没有新增后端、API Key、数据库或统计配置。Hash Router继续使用；不要把添加到主屏幕误称为离线支持。

## 发布顺序

1. 记录Cloudflare当前生产分支、部署ID、Git提交与访问地址（从控制台读取，不猜测）。
2. 分阶段检查PR、测试和构建；先合并PR #1，再按基础、报告、分享顺序合并后续PR。
3. 在Cloudflare将生产分支设为 main。若控制台未登录，由站长完成登录或按上述配置操作。
4. 等待新的部署成功；检查线上首页、两种问卷、结果恢复、卡片尺寸与二维码域名。确认二维码不是localhost或旧上游域名。
5. 在真实手机与网络验收之前保持测试版，不扩大推广。

## 回退

部署失败时保留旧生产部署；若上线后有阻断问题，在Cloudflare部署列表中回退到第1步记录的成功生产部署。记录问题和提交，在独立分支修复后重新部署。无需清除访客已有结果，本轮保留原结果键。草稿仅用于新版；题库改变时同步更新版本标识并提示重新开始。

## 访问与维护

页面按需加载，分享卡需网络下载导出代码；首次导出失败允许重试。清理网站数据会移除进度与结果，本地存储受限时显示提示并在当前页面保留结果。main分支更新前运行 npm test -- --run 与 npm run build。

每次发布更新验收记录：版本、测试结果、部署ID、时间、待测设备和已知限制。后续确认品牌名称和域名后，检查 title、manifest、图标、语言配置及海报二维码。
